# Foreign Trade Enterprise RAG｜外贸企业资料检索原型

[English README 与完整技术说明](README.md)

**这个产品事实现在是否有效，依据是什么？**

外贸团队需要从产品目录、操作流程与历史报价中查找信息。这个原型让员工检查回答所用的来源；新资料先进入审核，获得批准后才能成为当前事实。

**真实界面中的示例：** 一个产品的最低起订量（MOQ）依次经历四个阶段：**已批准 144 件 → 待审提案 180 件 → 批准 180 件并保留 144 件历史 → 更新检索索引，回答引用 180 件的批准来源**。待审或被拒绝的提案不能直接覆盖当前值。

**公开合成数据原型：** 虚构 Northstar 业务记录，真实应用截图；没有运行中的云端部署。

## 为什么有用

使用回答前，团队可以检查哪些信息当前有效、哪些属于历史、哪些尚未核实，以及变更为何获批。这是已演示的信息管理流程，没有测量企业实际节省时间、收入提升或生产效果。

## 技术与评估边界

系统使用 Python / FastAPI、SQL / SQLite、React / TypeScript、Qdrant、BM25 与 RRF。这里的 RAG 用于检索证据并从明确字段组装回答，**没有启用生成回答的大语言模型**。

公开演示默认使用确定性的特征哈希向量，不是神经语义嵌入。MiniLM 神经嵌入有可选实现，但公开指标没有验证其检索质量。[检索流程](README.md#rag-pipeline)

公开评估包含 70 个由开发代理编写的合成问题。20 个内部冻结保留问题的 **平均 Recall@5 为 92.5%**，表示前五条检索结果对预期来源的覆盖，不是答案准确率。该组自动答案检查为 85%；测试不是独立人工编写的盲测，引用检查也不证明答案语义正确。[完整分组与指标限制](README.md#evaluation) · [已知失败](docs/benchmark_analysis.md)

一个已记录的限制是历史问题的措辞未被识别时，系统可能回答当前值，即使引用本身有效。其他限制包括缩略型号匹配、流程阶段区分、小型合成语料、单进程本地数据存储，以及尚未完成的企业级部署验证。请查看 [Known limitations](README.md#known-limitations)。
